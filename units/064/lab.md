## 一 手算目标并检查实现

### 任务B 伯努利与KL

一个像素真实为1，模型概率0.8，算负对数概率；真实改为0，再算一次。若64个logit全为0，一张图的条件NLL是多少？这与亮像素数有关吗？把你的答案与terms函数的输出比较，注意代码接收logit而非概率。

四维后验均值全为1、对数方差全为0，求到标准正态先验的KL。再设均值全为0、对数方差全为0，检查KL为0。解释为什么exp(lv)进入KL，而exp(lv/2)进入重参数化抽样。

```python
import torch
import experiment as e
x = torch.zeros(2, 64)
mu = torch.ones(2, 4)
lv = torch.zeros_like(mu)
nll, kl = e.terms(torch.zeros_like(x), x, mu, lv)
print(nll, kl)
```

### 任务C 归约单位

假设一个批次平均每像素重建交叉熵为0.2，平均每样本KL为4。按本课归约，重建项是多少？β=1的总目标是多少？如果误把重建项保留为0.2而KL仍为4，相对权重改变多少倍？写出这个错误为何可能被误诊为“需要预热”。

### 任务D 日程边界与梯度

计算step=1、100、500、1000时的β。阅读beta_at，确认步从1开始，500之后饱和为1。用自动微分验证z=μ+exp(lv/2)ε对μ、lv的导数。冻结ε进行这个导数检查，不需要也不应该对随机种子求导。

在一个小批次上执行前向和反向，检查所有模型参数都得到有限梯度。梯度存在只证明计算图连通，不证明目标正确；因此仍需前面的数值手算。输入检查用异常，−O模式下也必须保留，避免生产运行悄悄跳过无效数据。

## 二 跟踪控制变量与训练证据

### 任务E 配对训练

检查train函数如何设初始化种子和独立训练随机流。对同一种子，恒定β与预热是否抽取相同批次和ε？如果为了记录图像额外调用全局随机数，是否可能改变后续训练？说明将评价随机流与训练流分开的价值。

确认三方案的网络架构、学习率、批量、训练集一致。只有预热改变前500步β，长恒定方案只改变更新总数。列出不能同时改变的项目：若把预热模型变宽、学习率也改掉，就无法把差异归因于日程。

### 任务F 三种基线的作用

用训练集像素平均值计算独立像素测试NLL。解释它为什么能学到边际亮度，却不能表达同一张图中多个像素共同属于一条线。随后比较恒定VAE与预热，而不是只拿预热战胜独立像素基线作为干预有效的证据。

阅读长恒定对照。它多用一倍更新，所以不能称为同预算比较；它回答“增加计算是否也能改变结果”。检查单元测试中的前缀一致性：恒定训练2步应与长恒定以base_steps=1运行的2步完全一致。

### 任务G 训练曲线解释

分别画NLL与KL，不先把所有方案的training_objective叠加排名。预热期间β变化，即使模型预测不变，目标值也会改变。选同一固定批次重新评价是另一种诊断，但必须标清它不是程序原本记录的随机批次曲线。

从results.json读取每方案各种子的active_dimensions、mu_variances和shuffle_mse_delta。当前基线是否表现为完全不使用z？如果四维都活跃、打乱编码使重建显著变差，你还能直接说“预热失败是因为未解决完全塌缩”吗？把观察与解释分两列写在草稿中，避免将推测混进事实。

## 三 主结果与不确定性

### 任务H 计算配对差

对五个种子分别算预热测试负ELBO减去恒定基线。报告全部五个数、平均数、样本标准差、胜出次数与质量差。不要先挑每方案最好的种子再相减，那比较的是不同随机起点下的精选结果。

按讲义公式算近似t区间，使用自由度4的系数2.776。说明这个区间覆盖哪一层随机性：训练种子，还是重新生成训练集，还是测试例抽样？五个种子共用一个数据拆分和固定评价随机流，所以它不包含所有层面。

### 任务I 执行预设判据

三个条件逐条写通过或未通过。即使质量护栏通过，只要主收益门槛不满足，整体就不能写“假设成立”。若均值差很接近0，应区分“没有支持预定收益”与“证明任何微小差异都不存在”。当前五个种子不是全世界VAE的代表。

### 任务J 可选测量核验

不重新训练，加载固定权重，把evaluate的draws从32增加到128，记录主指标变化。该操作只检查Monte Carlo测量精度。使用独立输出文件保存结果，不覆盖本课固定表。若微小种子差变号，解释为什么这不自动恢复“至少降低0.2”的主张。
