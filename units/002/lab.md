## 第002单元 实验指南

目标是把001的手算变成可从头重复的程序，并能说清每一种错误。请先读lecture.pdf。实验分为环境、最小脚本、分步计算、错误练习、Notebook重跑五段。建议预留两次学习时段；安装时间取决于机器和网络，不作为学习能力评价。

你只需普通CPU和少量本地空间来运行本讲程序，不需GPU、云服务或付费模型接口。Anaconda发行版本身占用的磁盘空间应以当前官方系统要求为准。数据完全合成，程序运行不联网，不上传文件。公开教学标签不能构成真正盲测。

## 一 先确定安装分支

先查自己的操作系统与处理器架构，再下载对应安装器。Windows可在“设置”中的系统信息查看系统类型；macOS在“关于本机”查看芯片或处理器；Linux可在终端用uname -m查看架构。命令的-m是选项。不要仅因电脑外观相似就给Apple silicon、Intel和ARM Linux使用相同安装器。

从[官方安装导航](https://www.anaconda.com/docs/getting-started/installation)进入本机的分支。当前网页和本讲核查日期可能不同；以官方当前系统要求为准。下载如需账号，按官网流程自己登录。阅读安装和软件源条款，理解之后再决定是否接受；本课不代替你的许可合规判断。单位或学校受管理的电脑请按管理员规定安装，不关闭防护软件、不绕过证书警告或访问限制。

### Windows

1. 打开[Windows图形安装说明](https://www.anaconda.com/docs/getting-started/anaconda/install/windows-gui-install)，确认当前支持的系统与64位安装器，保存到下载目录。
2. 双击官方安装器。阅读条款，再按自己的决定继续。通常优先当前用户安装；没有必要时不要以管理员身份启动，不覆盖未知的旧安装。
3. 检查安装目录。官方建议避免空格或特殊字符可能造成的兼容问题。高级选项含义不确定时先查看该页说明，不随意修改全局PATH或让所有软件改用新Python。
4. 安装完成后在开始菜单搜索Anaconda Prompt并打开。它已经为conda准备好命令环境。先执行conda --version；看到版本才进入第二部分。普通PowerShell找不到conda时，先用Anaconda Prompt定位，不要立即再次安装。

本讲没有在Windows上实际运行安装器。这里是经官方文档核对的操作路线，你的安装成功与否以本机验证为准。

### macOS

1. 在“关于本机”确认是Apple silicon还是Intel。打开[macOS图形安装说明](https://www.anaconda.com/docs/getting-started/anaconda/install/mac-gui-install)。截至核查日，官方说明已停止为Intel Mac构建新包，旧Intel安装器仍在归档。Intel用户必须先核查受支持的旧版组合或咨询管理员，不能下载Apple silicon安装器假装通用。
2. 对官方支持的Apple silicon机器，下载对应.pkg，双击启动，阅读条款与安装范围。官方图形安装流程目前使用/opt/anaconda3；希望在个人主目录安装者应使用同页链接的终端安装说明，不把不同安装方式的路径混写。
3. 依照官方安装器完成操作，打开或重新打开Terminal。先执行conda --version和conda list。能看到版本及包列表后，再创建本课环境。
4. 若出现安全或权限警告，核对来源并查官方故障说明，不绕过系统安全提示。不要因为某个教程写了旧Intel路径就照搬到Apple silicon。

本讲不承诺任意旧macOS或Intel组合都可安装；也未在macOS上做实机安装测试。这个限制与Python代码本身不使用系统专有API是两回事。

### Linux

1. 打开[Linux官方安装说明](https://www.anaconda.com/docs/getting-started/anaconda/install/linux-install)，按x86_64或对应ARM架构下载.sh文件。官方提醒某些ARM构建不适合特定树莓派配置，不能把aarch64当作所有ARM机器通用。
2. 建议按官网说明计算下载文件的SHA-256，与官方归档中同名文件的摘要比较。Linux命令是sha256sum后接文件路径。摘要不同不要运行，先重新核对下载来源与文件。
3. 在终端输入bash、一个空格、下载文件的实际路径。比如将文件拖入终端可帮助填入路径，但先检查结果。这里不提供会很快过期的固定版本文件名；不要把“实际文件名”几个字原样当作文件。
4. 读安装提示与条款，自行决定是否同意；确认安装目录，不覆盖未知环境。若选择conda初始化，它会修改当前shell的启动配置，使新终端识别conda，应理解这一效果。通常无须sudo。
5. 完成后关闭并重新打开终端，运行conda --version和conda list。找不到命令时，回到官方说明核对是否完成了当前shell的初始化，不随意执行网上来源不明的修复脚本。

## 二 创建并验证本课环境

以下是终端命令，不是Python代码。每行回车后看结果再继续。若已存在dl002，先确认是不是本课环境；不删除他人的环境，不覆盖正在用的项目。

```text
conda --version
conda create --name dl002 python=3.12
conda activate dl002
python --version
conda info --envs
conda list
```

检查创建计划、下载源和任何条款提示后再确认。安装失败时保存原始报错，区分网络、磁盘、权限、版本求解或条款问题；不要用忽略证书检查解决连接问题。只运行experiment.py不需安装数值库。

下列是进入Python后输入的语句。先在终端输入python并回车，再逐行执行。print显示内容，import载入标准库模块，点号访问模块中的名字。

```python
import sys
print(sys.version)
print(sys.executable)
exit()
```

在自己的实验记录中写下日期、系统、实际Python版本、conda版本和环境名。解释器路径应属于dl002。路径记录留在本机即可；公开提交时可隐去个人用户名。此处查的是实际运行对象，不能仅把环境名前缀当证据。

可选的environment.yml提供相同意图：名为dl002、Python 3.12系列，加Notebook所需工具。它不是跨平台逐字节锁文件。第一次手动创建环境和从文件创建是两条替代路线，不必先后各建一遍同名环境。选择文件路线时在本目录执行：

```text
conda env create --file environment.yml
conda activate dl002
```

为已创建的基础环境加Notebook工具，执行conda install jupyterlab ipykernel。这里安装的是界面与内核，不是模型计算库；仍应检查下载和条款提示。[官方环境资料](https://www.anaconda.com/docs/getting-started/working-with-conda/environments)

## 三 创建第一份文件并找到它

先建一个只放本实验的工作目录，把本单元完整下载或解压进去。目录里应直接看见experiment.py、experiment.ipynb和data。用代码编辑器新建first.py，输入以下两行。字符串是引号包住的文字，注释以#开始。

```python
# 输入3 偏移量1 的规则A
print("prediction", 2 * 3 + 1)
```

保存为UTF-8纯文本。Windows文件资源管理器显示扩展名后确认不是first.py.txt；macOS文本编辑器若用于此步，先选择纯文本模式。用编辑器的保存按钮把文件写入磁盘，再在终端运行。只改变未保存的编辑窗口，不会改变磁盘上的脚本。

终端用cd切换目录。路径中有空格时放在英文双引号内。Windows Anaconda Prompt中的cd /d可同时切换盘符；macOS与Linux的cd不使用/d。下面是示意，应把路径替换成自己的实际目录：

```text
Windows:     cd /d "C:\your-course\002"
macOS/Linux: cd "/your-course/002"
```

不要连同Windows:或macOS/Linux:标签输入。Windows用dir查看文件，macOS/Linux用ls。看见first.py后执行python first.py，预期输出prediction 7。找不到文件时先核对当前目录与完整文件名；这类错误通常无需重装Python。

然后运行python experiment.py。预期候选MAE为1.2、0.2、0.8；训练A为0.2、B为0；测试A为0、B为7；压力测试A为3。版本行与系统路径可能不同，下面的数值应相同。完整结果请与outputs/expected-result.txt比较。

## 四 在运行前先做预测

不要直接盯着现成答案修改程序。以下每步先纸笔写预期，再在新的临时脚本或Notebook副本中执行。保留课程原始文件，改动放到自己的副本。

1. 变量追踪。按顺序执行x = 3、bias = 1、prediction = 2 * x + bias、x = 4。此时prediction是多少？怎样才会变成9？写出每行执行后三个名字的值。
2. 类型区别。分别计算2 * 3、2 * "3"、1 / 5、7 == 8。写出结果与类型。不要用看起来一样的字符替代类型说明。
3. 列表对齐。写下train_x[2]与train_y[2]，解释为什么这个索引对应第三条记录。写出最后一个合法非负索引。
4. 循环追踪。用偏移量1逐条列出预测、绝对误差、累计误差。最后才算平均数。说明为什么总和为1而不是0。
5. 候选选择。独立完成偏移量0、1、2的三行评分表。确认比较只用了训练标签。解释同分规则怎样由升序与严格小于共同实现。
6. 函数追踪。对predict_b查询3和2.5，逐轮写出比较真假与返回时点。解释未命中返回0的位置为什么在循环外。

提交自己的预测记录，不只是重新打印提供的输出。答案详解在answers.pdf；先尝试，再核对。

## 五 故意报错与不报错的错误

随附error_examples目录有六个独立脚本。它们是故意失败或故意算错的教学材料，不是正常experiment.py的一部分。请一次只运行一个，先预测现象，再记录错误类型、关键行和最小修复。不要把这些文件混进Notebook正常顺序运行的主路径。

|文件|练习目标|你要观察什么|
|---|---|---|
|01_name_error.py|先使用后定义|错误中指向哪个名字|
|02_type_error.py|文本与数字混用|显示数字字符不代表数值|
|03_index_error.py|索引越界|长度5为什么不允许索引5|
|04_indent_error.py|漏掉缩进|哪一行应属于if代码块|
|05_reset_total.py|累计量放错位置|没有异常为何仍然算错|
|06_early_return.py|return提前结束|后面记录为何不再处理|

前四个运行会以错误结束，这是本组练习的预期。后两个正常结束但打印错误结果。主实验的“可运行”检查抓不到所有逻辑错误，所以需要已知答案和中间状态。观察英文最后一行；文件路径和行号帮助定位，不必逐字翻译全部跟踪信息。

修复01时先定义使用的名字；修复02时明确输入究竟应该是文本还是数字；修复03时选择合法索引而非随意补一行数据；修复04时让缩进表达预期的分支。修复05与06时，移动语句而不是把最终输出硬编码成0.2。

进一步变化：把训练第三条的8改为7，其他记录不变，先预测各候选训练MAE与选中偏移量。再把标签改为[2.5, 4.5, 6.5, 8.5, 10.5]，考察0和1同分时的规则。变化实验单独记录，不替换原始001数据。

## 六 启动并重跑Notebook

在已激活dl002的终端、且当前目录含experiment.ipynb时执行jupyter lab。若命令不存在，先确认环境，再执行前面说过的工具安装，不向base反复乱装。浏览器通常打开本地界面；没有自动打开时按终端给出的本地地址访问。不要把带访问令牌的链接发到公共群聊，不把服务改成任意网络可访问。

在文件列表打开experiment.ipynb，确认使用Python内核。第一个代码格打印版本；若怀疑选错环境，在一个临时格运行import sys与print(sys.executable)，核对后删除临时格或清除其个人路径输出。Shift+Enter通常运行当前格并进入下一格，运行前先阅读对应文字。

菜单名称会随Jupyter版本和界面语言略变。寻找“Restart Kernel and Run All Cells”或含“重启内核并运行全部”的命令；若无组合项，先重启内核，再从第一格执行全部。保存文件，检查执行顺序递增，主实验没有红色异常。仅点击“清除全部输出”不等于重启。

单独新建两格来练习隐藏状态：第一格bias = 1，第二格print(2 * 3 + bias)。顺序运行后，把第一格改成bias = 2但不运行，只运行第二格；解释为什么还是7。再运行第一格与第二格，观察8。最后重启内核，仅运行第二格，应出现NameError。这次失败是你主动演示缺少定义，不是正常实验Notebook的最终状态。

正式交付前回到原始完整Notebook，重启并全部运行。再关掉先前交互会话，回到终端重新运行experiment.py。两条路径应给出同一组模型结果。不要删除某个失败单元格后保留它以前创建的变量来“修好”文件。
