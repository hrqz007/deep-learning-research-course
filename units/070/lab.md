# 第070讲 实验指导书

本实验的完整交付是一项小规模、可审查的机制复现。你会运行20个分支，而不是只得到一张最高分截图。请先阅读计划，再看结果，避免让结果反过来决定问题。

## 一 运行前核对计划

阅读experiment.py中的PLAN，记录训练128、验证192、测试512，五个初始化种子，四种正则化模式，160次更新和主要指标。数据生成种子7001固定，测试部分不参与早停或超参数选择。

程序开始时先写plan.json并计算SHA256，再进入训练循环。这个顺序让代码执行可检查；它没有外部时间戳，所以只称固定执行计划，不称不可篡改预注册。若你修改计划，应另建运行目录并明确记录变更。

## 二 运行测试和完整实验

```bash
python -m unittest -v test_experiment.py
python -O -m unittest -v test_experiment.py
python experiment.py --output my_run
```

测试包括数据形状、拆分、相同种子下的参数逐张量一致、配对区间计算、Dropout期望与eval行为以及总更新预算。实验不需GPU和外部数据，安装依赖后可离线运行。默认outputs会覆盖，扩展使用my_run等新目录。

## 三 对照网络与优化过程

打开model(p)，确认网络20→64→64→2，两个隐藏层之后各有Dropout。四种模式只改变p与Adam的weight_decay，线性层参数量相同。这里使用Adam内的权重衰减参数，不是单独研究AdamW；不要在报告中偷换算法名。

每一步全批128样本，优化器更新后切换eval计算训练与验证NLL。训练曲线因此使用确定性eval损失，和更新时随机Dropout损失不同。查看代码即可发现这个定义，报告也应沿用它。

## 四 检查选择机制

每个history有160条记录。找出validation_nll最小位置，应等于selected_epoch；checkpoint中的epoch也应相同。测试NLL只在恢复选中参数后计算，没有逐步测试曲线用于选择。

任选两个模式，比较验证选中epoch是否不同。解释为什么最大预算相同不意味着最终模型实际经历相同步数。这是验证选择算法的特点，不能悄悄改为最后一步比较而保留原来的说明。

## 五 重载所有检查点

输出包含20份.pt文件，每份保存state_dict、seed、mode、p、weight_decay和epoch。只加载可信来源，使用weights_only=True。按p重建网络，加载参数，eval后用后512个样本重算NLL、accuracy和Brier，与results.json核对。

不要只抽一个“最好”模型。Notebook会遍历所有20份并执行数值检查。若某份不一致，应停止使用对应结果，核对选择深拷贝、模型结构和数据索引。

## 六 配对与交互计算

按相同seed匹配dropout与baseline，先做差再求均值。本次平均NLL差约-0.015111，五种子近似t区间[-0.035153,0.004931]。请手算至少一个种子的差，并解释为何区间只针对初始化变化。

再按四个模式计算L11-L10-L01+L00。均值约-0.001703，区间跨零。不要把它写成“两种正则化之间绝对没有交互”；当前运行数与设置不足以支持那种普遍结论。
