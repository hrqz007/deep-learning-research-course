# 第一次可重跑的研究练习实验

## 本次交付是一个可追查的过程

使用随附配置与合成数据，重做三次预先规定的训练子集运行，按主运行验证分数冻结模型，再核对测试标签。最后写三条描述性现象。实验与测试仅用Python3.12标准库，CPU、离线即可；Notebook另外需要JupyterLab和ipykernel。

先读讲义与005的数据拆分内容。本单元没有神经网络，没有付费API，没有真实设备数据，也不计算统计显著性。固定种子和完整记录的价值，是让别人能够检查过程，不能替代新证据。

## 一 阅读配置与名单

config.json规定主种子101、描述种子101/102/103、训练子集8条、候选偏移量0/1/2、固定系数2、MAE和模型同分时选择仿射规则。先复制一份手写实验计划，之后不要为了对上测试答案偷偷修改。

data/train.csv包含A至D四台设备各四行；validation.csv为E四行；test_inputs.csv为F四个输入；test_labels.csv只保存F对应答案。程序按编号对齐测试标签，并核对三部分设备不重叠。当前目标是新设备，不把每一行误当独立设备。

data/README.md说明全部生成方式。公开答案无法构成真正未知盲测；本实验仍要求冻结预测后再用答案核对，以练习正确的工作顺序。

## 二 先重算主运行

读取B3、D3、C1、B2、B4、A1、D2、A4这八条训练记录。对偏移量0、1、2分别计算总绝对误差8、2、8，除以8得到1、0.25、1。偏移量1获选。标签总和48，所以常数基线为6，训练MAE为2.25。

对验证设备E，仿射预测3、5、7、9与标签相同，MAE为0；常数6的MAE为2。根据主运行验证比较，冻结仿射规则及偏移量1。测试输入的冻结预测也为3、5、7、9，不需要测试标签。

写完预测后才核对F标签5、7、9、11，带符号误差都为-2，绝对误差都为2。报告同时写四条记录和一台设备，不能只写“测试样本数4”后暗示四个独立实体。

## 三 运行并查看产物

在本单元目录执行：

```bash
python experiment.py
python test_experiment.py
```

正常主脚本输出selected_model为affine、coefficient为2、bias为1、primary_seed为101、test_mae为2。测试应打印passed与十一组检查。失败时保留错误，不要手动修改结果文件冒充成功。

|每次运行目录内的文件|保留的信息|
|---|---|
|frozen_plan_and_predictions.json|配置、主种子、选定模型、测试输入编号与预测、预先已使用文件的摘要|
|all_descriptive_trials.json|三个种子的训练编号、候选分数、参数、训练与验证MAE|
|final_result.json|冻结模型的最终教学测试结果与范围|
|test_predictions.csv|每条测试标签、预测、带符号偏差和绝对误差|
|run_manifest.json|输入与源码版本摘要、运行版本、四个核心结果文件摘要|
|run_log.txt|本次实际完成步骤的顺序|
|run_status.json|running、complete或failed；失败时记录异常类型|

outputs是运行集合。每次调用自动创建新的run-0001、run-0002等编号目录，保留之前的所有运行，且不会把不同尝试的文件放在一起。先看对应目录的run_status.json，只有complete才代表本次完整完成。新尝试失败不影响旧目录；状态为running可能表示还在运行或曾意外中断，也不能当作成功。

## 四 从空会话重跑

打开experiment.ipynb，从第一格开始。先只调用prepare，它读取训练、验证和测试输入，返回冻结方案与所有种子记录，不读取测试标签。检查selected_train_ids是否与手算表一致，再查看两个模型的验证分数。

完成后调用run保存完整结果。重启内核并运行全部，所有单元应顺序成功，不依赖上次留下的变量。实验本在notebook_outputs集合中创建独立编号目录，不覆盖脚本outputs；再次全部运行会新增一次尝试。

制作时使用新Python进程中的真实IPython InProcessKernel逐格执行，未测试浏览器界面或外进程套接字传输。固定Python版本不等于在每种操作系统完成安装；核验边界保存在verification.json。

## 五 核对摘要和实际抽样

进入一次完成目录，打开run_manifest，将其中四个核心产物的摘要与重新计算的值比较。verify_artifacts若收到运行集合路径，会检查最新尝试，最新尝试失败时直接拒绝；也可明确传入某次目录检查历史成功。它不检查所有报告文件，只检查manifest实际列出的四项，不应夸大成整个文件夹完全未变的证明。

训练种子之外还要保留实际入选编号。对102和103逐条查看抽中了哪些记录，而不是仅记录最后偏移量。程序保存所有预定运行，主运行仍为101，不根据已经揭示的测试结果重新挑种子。

测试会运行两次完整实验并比较各自目录中的同名产物；另外启动新Python进程，从无关目录读取同一个脚本，核对最终结果。核心记录不含运行时间、目录编号和私人绝对路径，因此当前环境中内容可逐字节一致。

## 六 看失败检查在保护什么

测试在临时目录复制数据并删除测试标签文件。prepare仍应得到相同模型与冻结预测，证明这些决策不依赖测试答案；完整run则应在评价时明确失败。这次失败尝试目录中可以保留冻结方案，但没有最终结果，run_status必须为failed，不能借用早先成功运行的成绩。

回归测试还先成功运行一次，再把候选偏移量改为只有0并移走标签，向同一运行集合再次调用run。要求旧成功目录逐字节不变，新编号目录标为failed并保留偏移量0的冻结方案，不得带有旧final_result或旧run_manifest。对集合进行最新结果检查必须拒绝；只有明确选择旧目录，才能核对那一次历史结果。

然后测试把F的标签全部改成100，再次调用prepare。模型与预测仍应相同。这个检查比仅看代码里变量名叫不叫test更直接：它验证测试答案变化不会影响此前的决定。

把验证设备E改写为训练设备A，应触发拆分重叠错误。把训练子集大小改成17，应因超过16条训练池而被拒绝。最后给某个已记录结果文件多加一个换行，摘要检查应发现字节变化。测试只操作临时副本，不修改课程原始CSV。

## 七 写三条待解释现象

第一条可写：三个种子的训练MAE不同但偏移量相同。检查入选记录组成，再提出一次只使用训练与验证资料的对照。第二条可写：三个不同的常数预测在验证上同分。展开四条误差，说明平均掩盖了哪些差异。第三条可写：验证全对而测试一致低估2。区分观察与可能解释，并说明下一步为什么需要新的适当数据。

每条都包括具体数字、可找到的记录、至少一个未被当前结果排除的解释，以及一项能够增加证据的检查。不要用“模型已经稳定”“证明设备漂移”替代这些内容。即使作者知道合成数据的生成设计，真实研究仍需建立对应证据。
