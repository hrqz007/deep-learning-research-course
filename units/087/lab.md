# DL087 实验：配对消融与成本评价

## 研究问题

在同一80题、同一3个故障种子、同一两次调用上限下，规范化、重试和引用各改变什么？交付完整轨迹、分组指标、配对bootstrap差值及质量/模拟成本图。不得把模拟成本单位换成毫秒或美元。

## 1 环境与完整运行

核心使用Python和NumPy，完整依赖见requirements.txt。

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python experiment.py
python -m unittest -v test_experiment
python -O -m unittest -v test_experiment
```

会生成80题冻结文件、40条语料、1200条运行记录（5版本×80题×3种子）以及metrics.json。脚本无网络调用，所有工具故障由固定伪随机序列决定。

## 2 先审查任务，再看成绩

打开tasks_frozen.json。四组各20题，前两组expected含正确记录与数值，后两组期待abstain或denied。检查id唯一。task_hash是整个任务结构的哈希，包括标准答案；改一个查询就应改变哈希。

阅读main中visible的构造：只传id与query给控制器，不传group和expected。尝试删去expected后直接run_system，仍可运行。金标准只供score使用。代码中查询解析与语料读取才产生答案，不能按题号查答案。

## 3 挑一题检查整条轨迹

选T020，即第一个别名题。full把sample-20变成E020，读取正确记录；no_normalization无法识别别名而落到首条E000，因此失败。这里失败是预先定义的规则缺口，不是自然语言模型语义能力测量。

选一个首次工具调用发生transient_failure的任务，比较full和no_retry在同一种子下的events。两者遇到同一故障；full允许第二次，no_retry提前停止。若不同方法用不同随机序列，就难以把差异归因于重试。

## 4 分开计算指标

正式成功要求正确值及正确citation。value_only_score不要求citation，是故意设置的宽松诊断。retrieval_recall_answerable只对40个可回答题计算，不把缺失和权限题作为负例填零。

读取no_citation：正式成功0.5，但value_only_score为1。说明只验数值会漏掉全部40个可回答题的证据缺失。读取no_retrieval：成功0.25来自20个缺失题；它不是强的无检索LLM基线。

## 5 配对bootstrap

每个版本有3×80成功矩阵。先沿种子维度平均，得到80个任务级分数，再对任务索引成对重采样4000次。严禁把full和消融版本分别打乱，因为配对关系包含相同题目难度和故障。

本次full−no_retry约0.12917，区间约[0.0875,0.1750]。这描述当前经验任务分布的抽样不确定性，不包含真实模型训练、未知任务类型和不同故障机制。四组固定权重研究可扩展成分层bootstrap，本课未实现。

## 6 预算和成本

所有版本最大工具尝试数为2；no_retry主动只用1次，并非被给更小资源上限。平均实际成本不同，所以应一起报告。定义成本1+2A，A为工具尝试数；no_retrieval保留1单位固定控制开销。

full平均约2.2583单位，no_retry为2。写清更高成功率伴随额外恢复成本。p95也是该模拟成本分布的分位数，不是在线尾部延迟。对真实服务，需要新的测量协议和实际硬件、网络、模型版本记录。

## 7 预先注册的扩展

可以把首次故障概率改为0.1、0.3、0.6，先写出预期：重试收益应随故障覆盖增加而变化，但本模拟第二次必成功，使恢复过于理想。更真实扩展应加入连续失败、执行后丢回执和时间预算，并重新定义评分。

也可增加未见别名，使固定正则规则失败。不要把这些题添加后只给full特别修补而不重新评估全部基线。保留旧版本及差异说明，避免任务集随着方法一起漂移。

## 8 验收

14项测试普通及优化模式均通过；任务组与唯一id、金标准隔离、引用要求、预算、哈希变化及bootstrap边界全部测试；1200条轨迹保存；报告组别成功、召回、工具故障、正式与宽松分数、配对区间、模拟成本。
