## 第一站 先用小数值检查目标

数据生成器保存两个任务各768训练、192验证和384测试样本。二维点接近半径1.7的环；图像由带随机像素翻转的横线或竖线构成。图像是真正0/1数组，不是把普通灰度图简单缩放成0至1。验证集随包保留，但本实验不据它选择超参数；所有配置提前确定。

先运行KL手算：mu=(1,0)、方差=(4,1)，即logvar=(log4,0)，预期KL约1.306853。再令mu与logvar都为0，预期KL为0。解释第二个例子对应标准差1，而不是标准差0。

```python
import torch, math
from experiment import kl_standard, reparameterize
mu = torch.tensor([[1., 0.]])
lv = torch.tensor([[math.log(4), 0.]])
eps = torch.tensor([[.5, -1.]])
print(kl_standard(mu, lv))
print(reparameterize(mu, lv, eps))
```

第二个输出应为(2,−1)。Notebook另对z1+z2求导，预期mu梯度(1,1)，logvar梯度(0.5,−0.5)。这是局部梯度校验，不是训练时完整损失的一步梯度。

接着检查高斯常数：D=2、sigma=1、预测等于输入时每例NLL应为log(2π)≈1.837877。二值64维零logit时NLL应为64log2≈44.361420。若你得到0.693147，说明做了每像素平均，而非本课每例像素和。不要为“让数值接近”随意调beta，先检查定义。


检查保存的weights文件共12份，均为普通npz数组。plot_data保存每例测试评估、均值重构、先验样本和训练轨迹。不要把训练轨迹中最后一批的loss当作完整测试负ELBO；两者数据、噪声数量与beta可能都不同。

## 第三站 诊断坍塌并审查干预

对每种任务、每个种子，分别抄下standard、high_beta与restore_beta的KL、负ELBO、mu方差和shuffle_nll_delta。先看KL是否极小，再看mu是否随输入变化，最后看打乱mu与x配对是否改变重构。三项一致比一个模糊图更有说服力。

二维高beta的KL约1e−4量级，图像约1e−5量级；restore_beta恢复到大于1的量级。这里的数量级来自本数据与尺度，不是可搬到所有VAE的阈值。beta100是人为压力，结论应明确“诱发坍塌”，不要写成标准beta1必然坍塌。

观察第300步之前的两条高beta前缀，它们应逐数相同。后半段只改变beta，网络、优化器状态、批次和噪声序列不改。若另从随机初始化训练一个beta1模型，然后称它“恢复”，就无法回答同一个已坍塌模型是否能重新利用潜变量。

图像恢复配置虽优于high_beta，但负ELBO仍约23.08至23.37，差于标准约19.97至20.63。请保留这种不完全恢复，不把二维结果扩写成两个任务都全面成功。提出解释时可以谈恢复步数和优化路径，但本实验没有分别验证这些原因，因此只能标成假设。

## 最后一站 记录限制和排查错误

一段完整报告应包含两种观测模型、nat/例归约、测试MC次数、两个种子、全部配置与单因素干预。明确负ELBO是估计的下界目标，不是精确边缘似然；高beta训练目标不同于最终报告的标准负ELBO；连续二维NLL允许负值。

如果KL明显为负，检查logvar是否被当成log标准差；如果换输入维度后训练行为剧变，检查像素和与平均；如果生成图始终灰度却声称二值样本，检查是否漏了伯努利抽样；如果restore前缀不一致，检查随机数生成器、初始化与更新顺序。
