## 第059单元 从视图配对到冻结探测

本实验要让你亲手核对三件事：正样本索引有没有写对，增强有没有保留下游目标，线性探测有没有改动编码器。完成时应得到12行结果、12份编码器权重、12份探测器权重、6张图和一个无错误且有输出的Notebook。所有数据原创合成，无网络下载、GPU或账号要求。

### 准备环境与认识文件

推荐Python 3.12，安装requirements.txt，CPU版PyTorch可从其官方安装页面选择。PDF构建依赖单列在build-tools，不运行PDF重建也能学习与重跑实验。首次安装可能需要网络，安装完成后数据、训练、测试与Notebook均可离线运行。

```bash
cd units/059
python -m venv .venv
# 按操作系统激活环境后
python -m pip install -r requirements.txt
python test_experiment.py
python -O test_experiment.py
```

若你只下载了单元文件，直接进入059目录即可，不需要前58讲。requirements.txt中的版本是本包实测版本或兼容范围，不保证任意未来版本逐位相同。遇到import错误先确认终端与Notebook选择同一个Python环境，而不是通过改损失函数来“修复”环境。

先打开outputs/protocol.json，抄下B、温度、步数、标签预算和种子。预先写下判断：保语义增强应优于破语义增强；但不能假定它每个种子都接近监督上限。把预测写在运行前，有助于避免看到结果后重新发明研究问题。

## 第一站 检查数据和一个手算基准

打开experiment.ipynb，从第一格开始顺序运行。若使用课程根目录启动，Notebook的路径探测会找到units/059；若从其他目录启动而找不到，程序会清楚报错。不要把输出粘贴成“已经运行”的代码格。

第一段显示三种划分形状，应该分别为768×8、192×8、384×8。各划分每类平衡。前四维来自角度，后四维来自独立干扰。用图01观察“信号可分、干扰无关”的设定；这里的颜色来自标签，只用于解释，不进入对比目标。

接着用a1=(1,0)、a2=(0,1)、b1=a1、b2=a2核对InfoNCE。写下128视图场景之前，先理解4视图：每个锚点3个候选，其中一个正样本、两个负样本。τ=1时应得到约0.551445。Notebook会调用自动微分显示梯度，它核对的是程序梯度有限，而手算才说明目标正确。

```python
from experiment import info_nce
import torch
x = torch.eye(2)
print(info_nce(x, x, temperature=1.0))
```

再令三行嵌入完全相同，损失应为log5，约1.609438。把温度改为0，应抛ValueError。不要删除输入检查让程序继续算出NaN；报错是对无效问题的正确回应。

检查增强时，保语义视图的前四维平均平方变化应很小，后四维变化明显。破语义增强则会改变角度。请用自然语言解释：相同实例索引仍然配对，但它的目标含义已经变化。标签没有参与训练，不代表标签所对应的信息会自动被保存。

## 第二站 完整重训并保护参考输出

Notebook的完整运行会把新训练结果写到notebook_replay，不覆盖随包outputs。也可以在终端重跑到自己的目录：

```bash
python experiment.py --out my_replay
```

四方法乘三个种子共12个编码器，其中随机方法不训练，另外9个各350步。每一步抽64个原始输入，有放回抽样；不是把数据按顺序遍历350轮。对比配置每批生成128个视图。CPU单线程，实际耗时依机器而变。进度没有每步刷屏不等于卡住，结束后会打印全部12行。

读代码时在纸上画出“输入→编码器→投影头→对比损失”和“冻结编码器→线性探测”的两条路径。探测器使用h而不是z。随机、对比与监督的编码器架构相同，但监督预训练头和对比投影头的作用不同，也使用了不同的标签信息。

检查run函数中的before状态副本。fit_probe处理NumPy表示，不接受编码器参数；拟合后再次比较全部编码器张量。若换成BatchNorm，除了参数还必须考虑running_mean等缓冲区。不要只看optimizer中有没有encoder就宣称完全冻结。

重训完成后运行独立测试：

```python
from test_experiment import main
main("my_replay")
```

测试会要求全部配置和全部权重存在，再从保存权重重新计算测试表示、探测器和得分。如果只删掉一个不理想的种子，测试应失败。不同版本硬件可有微小浮点差异；明显的准确率变化要核对版本、随机数生成和CPU线程设置，不能直接覆盖参考结果并宣称等价。

## 第三站 用固定协议比较而不是挑图

建立一张自己的记录表，行是方法，列至少包含三个种子的准确率、均值、范围、标签预算。先写所有数字再写结论。保语义对比均值约67.80%，范围约57.81%至83.85%，变化不小。随机约30.03%，破语义约21.35%，监督约99.65%。这些只是本固定数据划分上的描述统计。

图02只画5901，图03把三个种子全部显示。前者帮助理解几何，后者避免一个漂亮图代表全部运行。标准差较大的破语义表示可能编码了很多干扰，不能把它叫作常量坍塌。训练loss和下游准确率回答不同问题，把两个指标分开记录。

### 一个安全的增强消融扩展

复制脚本到自己的探索目录，不改参考outputs。选择保语义噪声强度0.02、0.04、0.08三个值，保持数据、模型、步数、种子、探测前缀和正则相同。在开始前约定用验证集平均准确率选一个强度；最后只对该强度报告一次测试。若已经看过原测试结果，就诚实把它叫探索性重复，不声称完全未见测试。

本包已经完成的增强消融是“替换干扰”对比“替换信号”。上面的连续强度实验只是练习建议，未随包执行，不要把建议当作已有结果。另一个扩展是只用128标签的监督预训练，它回答不同的标签效率问题，也不能拿当前768标签参考冒充它。

### 提交自己的结论

用一段完整文字说明目标、控制条件、三种种子和限制。附上一个手算、一次失败输入检查，以及冻结状态的证据。好的结论不是“模型学会了语义”，而是“在指定象限任务和冻结线性读出中，保留角度的视图产生了更可用的表示”。

## 排错与完成清单

若loss为NaN，先检查输入有限、温度大于0、是否使用稳定交叉熵、归一化是否防除零。若loss看似正常而probe差，检查增强是否破坏目标、是否读取h、探测标准化是否只由训练前缀拟合。若测试重放失败，先确认weights与probe属于同一方法和种子，文件没有被其他运行覆盖。

若Notebook找不到experiment，调整启动目录，不要在sys.path里写发布者电脑的绝对路径。若图中文字变成方框，安装官方Noto CJK字体后重画；这是渲染依赖，不应影响保存的数值结果。PDF源文件可独立阅读，预生成PDF已经包含中文字体。

完成时逐项核对：

- 四视图手算与程序约0.551445一致；常量B=3约1.609438
- 温度0被明确拒绝，普通和-O测试均通过
- results共有12个唯一配置，编码器与probe各12份
- 新运行写在独立目录，随包outputs仍未改变
- 编码器状态在probe前后完全相同
- 解释监督预训练额外使用768标签，未声称公平标签预算
