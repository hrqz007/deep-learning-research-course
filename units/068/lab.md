# 第068讲 实验指导书

这份实验把一个真实训练的小模型交给第二个执行对象，并检查预测语义有没有变。完成后你应能说明：导出文件由哪个模型产生、接受什么输入、逐样本差异多大，以及计时究竟包含哪些步骤。实验不需要GPU或外部数据下载。

## 一 准备与产物

在本单元目录创建独立Python环境，按requirements.txt安装依赖。已提供PDF可直接阅读；只有重建PDF才需要系统的Noto CJK字体与Pango支持。默认运行会覆盖outputs，所以第一次探索推荐另存目录。

```bash
python -m unittest -v test_experiment.py
python -O -m unittest -v test_experiment.py
python experiment.py --output my_run
```

my_run中会生成data.npz、model.pt、两份.pt2导出文件与results.json。只加载自己生成或可信来源的文件；.pt2是程序资产，不应因为扩展名不同就当作无风险文档。权重读取使用weights_only=True，但仍不对未知来源文件提供安全保证。

先阅读experiment.py的data与Model。记录数据总量1152、训练768、测试384，四个输入列的潜在尺度与偏移。标签虽然由潜变量确定，网络收到的是原始特征；均值和标准差只从训练部分计算。测试集没有用于调参，本课固定180次更新。

## 二 先检查训练闭环

运行程序后，查看history里从第1到180次更新的记录。每个记录包含训练时随机Dropout下的损失和eval状态测试准确率。二者不是同一模式、同一数据集上的数值，不能把它们当作直接可相减的训练与测试损失。

这份固定输出的最终准确率为0.989583，即384个测试样本中380个正确。你重跑时先检查版本与线程配置，再按容差比较数值；延迟不应要求完全相等。记录“数值可复查”和“性能会波动”这两个不同层面的结果。

## 三 检查真正保存下来的状态

载入model.pt并列出键名。除了各层权重，还应看到mean、scale，以及BatchNorm运行统计量。用测试样本的原始特征作输入，对比手工标准化后通过net的结果。这个检查说明预处理确实进入了模型，而不是只在训练数据管线里存在。

将正确分支与错误分支比较：错误分支直接调用m.net(test)，跳过mean与scale。固定输出准确率降为0.372396。请同时检查最大logit差，解释为什么单个样本碰巧预测正确不能洗掉整体的输入语义错误。

## 四 导出与形状边界

程序分别用[1,4]和[32,4]示例输入进行strict导出。保存以后重新读取，再用返回的module预测。逐样本核对并不是只比较第一条样本：batch1循环384次，batch32循环12次，最后按顺序拼接。

从export_checks抄下最大绝对logit差和类别不一致数。本次两种批次类别不一致都为0，batch1最大误差约3.81e-6。尝试把[2,4]输入batch1图，确认形状限制触发。不要为了让示例“跑通”而去掉这项检查；它本来就是契约的一部分。

扩展时可建立新动态批次分支，但应保留原静态结果，添加允许范围与边界测试。不能把本课静态文件改名成dynamic后声称支持动态输入。

## 五 检查eval与inference的独立性

复制模型，然后在train状态、inference_mode内对同一批样本预测两次。记录最大差异。再切换eval重复比较。请解释Dropout与BatchNorm各自发生什么，为什么使用副本可以避免改变正式模型的运行统计量。

入口测试包含四种请求：合法float32 [1,4]、含NaN、错误列数、float64。后三种应明确拒绝，prediction为None。本课不为非法数据补0，也不输出占位类别。若你选择自动转换类型，应把该变化写入合同，并补上范围和精度测试。

## 六 读懂计时而不夸大

timings每项含120个原始微秒数，p50、p95、p99和平均值。先手算一个小数组的linear分位数，再用保存的样本核对程序输出。不要仅复制图上的最高吞吐值；同时记录线程数、预热30次、CPU、输入在内存、顺序调用这些条件。

cold保存5次加载加首次调用的毫秒数。此时进程和库已启动，它没有测完整冷启动。把两个概念分别写入实验报告：模型稳态调用；暖进程中的资产重新加载。fresh_process另外保存每种批次三次全新Python子进程的实测，父进程spawn_to_exit_ms包含启动、import、加载、首调和退出；子进程import_load_first_call_ms只计导入开始到首调完成。检查两个时间的区别，不要把操作系统缓存未清除的启动称为无缓存磁盘测试。若要测容器或HTTP服务就绪，应另设实验。

## 八 研究任务与提交要求

选择一个额外问题：不同预热次数是否改变尾部统计；不同批次是否提高样本吞吐；或者遗漏一项输入验证会怎样影响失败行为。先写问题、保持不变的条件和允许改变的变量，再运行。不要一边改变线程、批次与模型，一边把所有变化归因于导出。

提交一页实验结论，附环境版本、实际命令、输出目录、数值一致性、原始计时位置以及至少两条限制。结论必须能被另一位读者用文件复核。真实服务器可作为后续工作，但本讲的验收不要求开端口、连接付费API或上传数据。


### 逐步设计一个批处理扩展

先保持网络权重与输入不变，只比较batch1和batch32的调用时间。每组都预热同样次数、保存同样数量的原始观测。按照两种顺序各做一遍：先单样本后批次，以及先批次后单样本。若顺序影响很大，应先检查CPU负载与缓存，而不是直接宣布某个模式胜出。

接着把目标分成两项。第一项是输入已准备好的计算吞吐，单位为样本每秒；第二项是一个新请求从到达到返回的响应时间。第一项可以从本课微基准估计，第二项还需要到达过程与凑批等待。可以先写一个队列模拟，但图和结论必须明确标注模拟假设，不得写成实测服务器延迟。

### 组织一份失败用例记录

每个失败用例记录输入类型、形状、是否有限、期望状态和实际状态。NaN、Inf、错误列数、错误批次和嵌套长度不齐应分别列出，不要只写“非法输入通过测试”。再用一个故意抛出RuntimeError的替身模型检查后端不可用路径：系统应返回unavailable，prediction为空，而非一个默认类别。

这条路径是可控降级，不等于已经实现自动切换备用模型。若未来要加备用模型，先确定它的版本、可接受输入、质量门槛和启用条件，再独立验收。不能为避免异常而调用任何碰巧存在的旧权重。

### 检查结论是否越过证据

逐句标记报告中的结论：由数据直接观察、由公式推导、属于假设或尚未验证。比如“导出后类别一致”应给384个样本的检查范围；“所有输入永远一致”不被当前实验支持；“图执行一定比eager快”也不成立。把范围写进主句，读者才不必到脚注寻找关键限制。
